# M6 — History Backfill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Every port task uses `/port-module` and ends with a `gchat-port-auditor` review. Steps use checkbox (`- [ ]`) syntax.

**Goal:** When a Google Chat portal is created (or needs history), populate the Matrix room with past messages — flat rooms via `list_messages`, threaded spaces via `list_topics` + per-topic `list_messages` — including their reactions, via bridgev2's `BackfillingNetworkAPI`.

**Architecture:** Implement `bridgev2.BackfillingNetworkAPI.FetchMessages` on `GChatClient`, driving the M1 `ListTopics`/`ListMessages` RPCs with cursor-based pagination, converting each Google Chat message to a `BackfillMessage` (reusing the M2–M5 `msgconv` conversion via `ConvertMessage`). Two strategies keyed on the portal's `PortalMetadata.ThreadsOnly`/`ThreadsEnabled`: flat (message pagination) and threaded (topic pagination, then per-thread message pagination via `ThreadRoot`).

**Tech Stack:** bridgev2 `BackfillingNetworkAPI`/`FetchMessagesParams`/`BackfillMessage`/`BackfillReaction`, the M1 client, M2–M5 msgconv, `networkid.PaginationCursor`.

### Task 2: FetchMessages for threaded spaces (topic + per-thread pagination)

**Files:** Modify `pkg/connector/backfill.go`. Test: extend `backfill_test.go`.

A `FetchMessages` call WITH `params.ThreadRoot` paginates that topic's messages via `ListMessages` (topic-scoped). Match Python's threaded strategy.
