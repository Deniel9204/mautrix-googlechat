# M5 — Media Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Every port task uses `/port-module` and ends with a `gchat-port-auditor` review. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Google Chat attachments (images, files) bridge to Matrix (download + streaming reupload); Drive/Meet/YouTube link annotations surface in Matrix; and Matrix media uploads to Google Chat — the last gated on Google's broken upload endpoint (issue #114), shipping either working or cleanly disabled.

**Architecture:** Two new client-library modules in `pkg/gchatmeow` (`download.go` — attachment URL building + redirect-following download; `upload.go` — resumable upload), consumed by the connector's inbound conversion (extra message parts via `intent.UploadMediaStream`) and outbound send (`HandleMatrixMessage` media branch → `UPLOAD_METADATA` annotation).

**Tech Stack:** `pkg/gchatmeow` `Session` (cookie/host-allowlist HTTP), bridgev2 `MatrixAPI.UploadMediaStream`/`DownloadMedia`, the M3 msgconv, `go.mau.fi/util` mime helpers.

## Global Constraints

- All M0–M4 Global Constraints bind (module path, pins, `-tags goolm`, layering: **gchatmeow does the HTTP for media (download/upload), connector does NO net/http** — the connector calls gchatmeow for bytes/URLs and uses `intent.UploadMediaStream`/`DownloadMedia` for the Matrix side; msgconv only converts; proto2; frozen IDs; plain commits, NO AI/session trailers).
- Reference: Python `maugclib/client.py` (`upload_file` ~275, `download_attachment` ~182) + `mautrix_googlechat/portal.py` (`_process_googlechat_attachment`, `_preprocess_annotations`, `_download_external_attachment` ~1456, outbound `upload_file` ~1099). **purple-googlechat** (`googlechat_conversation.c` ~1665-1750, actively maintained through 2026) is the reference for the CURRENT upload wire shape — diff it against Python's to catch any #114-related change. bridgev2 media at `$REF/mautrix-go/bridgev2/matrixinterface.go`. (`$REF` = `/Users/danielagoston/utmshared/Projects/git/generalclaude/mautrix/_reference`.)
- Cookie/host rule (from M2/Task-3): attachment hosts vary — `*.google.com`/FIFE get auth cookies; **`googleusercontent.com` and other hosts must be fetched WITHOUT cookies** (the M2 cookie-allowlist already enforces this in `Session`; download must route external hosts through a cookie-less path). Follow ≤10 redirect hops. Size caps from config/bridgev2 `RoomFeatures.File`.
- **Issue #114**: Google's `/uploads` endpoint has returned HTTP 500 since ~Feb 2026. M5 implements the upload with the correct (purple-googlechat-current) wire shape; the live round-trip is unverifiable here (test account throttled — docs/research/10). On a persistent upload failure the connector must return a clean bridge-state/MSS error, not a silent drop. The exit notes upload as live-unverified.
- Multi-part convention (frozen `gcid`): text part `""`, attachments `att_<n>`. The M3 B4 fix (text+file coexist) becomes real here.
- connector no net/http. Working dir = repo root; branch `m5-media`. Commit after every task.

### Task 1: gchatmeow attachment download (download.go)

**Files:** Create `pkg/gchatmeow/download.go`, `pkg/gchatmeow/download_test.go`. Port of `maugclib/client.py` `download_attachment` + `portal.py` `_process_googlechat_attachment` URL building.

**Interface:**
```go
// AttachmentURL builds the download URL for an UPLOAD_METADATA annotation.
// isImage → the FIFE image URL with sz=w10000-h10000; else the DOWNLOAD_URL.
func (c *Client) AttachmentURL(meta *proto.UploadMetadata) (string, bool /*isImage*/, error)
// DownloadAttachment fetches an attachment URL, following redirects (≤10),
// sending auth cookies ONLY to *.google.com hosts (cookie-less otherwise),
// enforcing maxSize. Returns (data, mime, filename).
func (c *Client) DownloadAttachment(ctx context.Context, url string, maxSize int64) (data []byte, mime, filename string, err error)
```
Mandatory (each a test): FIFE image URL built with `sz=w10000-h10000` + `get_attachment_url` query (attachment_token etc.) for images; DOWNLOAD_URL for non-images; redirect following capped at 10; cookies sent to `chat.google.com`/FIFE but NOT to `googleusercontent.com`/external (reuse `Session`'s host allowlist — the download must use the cookie-less path for non-google hosts, mirroring Python's separate cookie-less session); `maxSize` exceeded → a `FileTooLargeError`-style sentinel (add to errors.go); mime/filename from headers.

Grep the proto for `UploadMetadata` (attachment_token, content_type, name), `get_attachment_url`. Tests via httptest (redirect chains, size cap, cookie presence/absence per host).
- [ ] **Step 2–4:** RED → implement → GREEN.

### Task 2: gchatmeow resumable upload (upload.go)

**Files:** Create `pkg/gchatmeow/upload.go`, `pkg/gchatmeow/upload_test.go`. Port of `maugclib/client.py` `upload_file` (~275), cross-checked against **purple-googlechat** `googlechat_conversation.c` for the current wire shape (issue #114).

**Interface:**
```go
// UploadFile performs a resumable upload to /uploads and returns the parsed
// UploadMetadata to attach to an outgoing message.
func (c *Client) UploadFile(ctx context.Context, groupID string, data []byte, filename, mime string) (*proto.UploadMetadata, error)
```
Mandatory: the resumable protocol — POST `x-goog-upload-protocol: resumable`, `x-goog-upload-command: start`, content-length/type/filename headers → read the upload URL from the response header → PUT/POST the bytes with `x-goog-upload-command: upload, finalize` → the final response body is **base64 of a binary `UploadMetadata`** (decode it). Copy the exact headers/URL from client.py; where purple-googlechat differs (a #114-era change), match purple-googlechat and note it. A non-200/500 from `/uploads` → a clear error (the #114 path).
